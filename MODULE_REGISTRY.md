# System Assistant Module — Specification v0.1

**Module ID:** SYS-ASSIST
**Category:** Auxiliary / User-Facing
**Status:** Draft
**Version:** 0.1
**Date:** 2026-08-27

> Документ содержит разделы 1–4 стандарта TIP Module Design Standard (17 разделов).
> Разделы 5–17 подлежат оформлению после утверждения границ модуля.

---

## 1. Purpose

System Assistant отвечает за рабочее окружение трейдера и административные задачи вокруг торговли.

Модуль обеспечивает техническую готовность рабочего места к торговому дню и снимает с трейдера рутинные административные операции, не связанные с содержанием торговых решений.

Модуль не участвует в торговом процессе. Он не анализирует рынок, не формирует идеи, не оценивает сделки и не влияет на решения трейдера.

**Проблема, которую решает модуль.** Техническая неготовность рабочего места обнаруживается в момент, когда она уже мешает работе: отсутствует соединение с брокером, не установлено обновление, закончилось место под данные, не пришли данные от поставщика. Обнаружение такой проблемы во время премаркета или сессии стоит трейдеру времени в наименее подходящий момент. Модуль переносит обнаружение на этап до начала работы модулей TIP.

## 2. Design Principles

**2.1. Read-only в первой версии.**
v0.1 работает исключительно на уровне доступа Read. Модуль наблюдает и сообщает, но не изменяет состояние системы. Уровни Prepare и Execute вводятся отдельными версиями после накопления опыта эксплуатации.

**2.2. Завершение до старта модулей TIP.**
Проверка выполняется и завершается до запуска первого модуля торгового дня. Модуль не выполняется параллельно с модулями TIP, чтобы исключить конкуренцию за внешние подключения (в частности, за лимит одновременных сессий Interactive Brokers).

**2.3. Разделение окружения и содержания.**
Критерий принадлежности задачи модулю: задача относится к рабочему окружению или к административному обслуживанию торговли. Задачи, относящиеся к содержанию торговли (рыночные данные, события эмитентов, оценка сделок), передаются профильным модулям TIP и в System Assistant не обрабатываются.

**2.4. Отсутствие второго источника данных.**
Модуль не дублирует функции существующих модулей TIP. При пересечении области (например, сообщение брокера, содержащее рыночную информацию) приоритет имеет профильный модуль.

**2.5. Отсутствие доступа к секретам.**
Модуль не хранит, не читает и не передаёт пароли, токены и ключи API. Проверка работоспособности учётных данных выполняется по факту успешного или неуспешного подключения, без доступа к значению секрета.

**2.6. Необратимые действия исключены.**
Действия с внешними финансовыми или юридическими последствиями не входят в область модуля ни на одном уровне доступа.

**2.7. Отказ модуля не блокирует торговлю.**
Недоступность System Assistant не препятствует запуску модулей TIP и не останавливает торговый день. Модуль является вспомогательным.

## 3. Responsibilities

### 3.1. Проверка готовности рабочего места (Read)

| Область | Что проверяется |
|---|---|
| Брокерское подключение | Запущен ли TWS; установлено ли соединение с IBKR; активны ли подписки на рыночные данные |
| Поставщики данных | Доступность Polygon; доступность TradingView |
| Программное обеспечение | Состав установленного ПО и версии; наличие непримененных обновлений |
| Конфигурация рабочего места | Активная конфигурация (Home Mode / Travel Mode); определяются ли все подключённые мониторы |
| Ресурсы машины | Свободное место на диске; доступная память; загрузка процессора |
| Хранилище данных | Свободное место с учётом Retention Policy v0.1 |
| Целостность журнала | Наличие записей за предыдущий торговый день; отсутствие пропусков и повреждений файлов |

### 3.2. Технические сообщения Interactive Brokers (Read)

Модуль читает сообщения брокера и отбирает технические: плановое обслуживание серверов, прерывания сервиса, изменение требований по марже, изменение статуса подписок на данные.

Сообщения, содержащие рыночную информацию (корпоративные события, отчётности, изменения условий заимствования бумаг), модулем не обрабатываются и передаются профильным модулям TIP.

### 3.3. Административная почта (Read)

Отбор и краткая сводка технических и административных писем: счета, подписки, уведомления сервисов, обслуживание.

### 3.4. Формирование отчёта готовности

По результатам проверки модуль формирует отчёт с перечнем обнаруженных отклонений. Отчёт носит информационный характер. Устранение отклонений выполняет трейдер.

## 4. Module Boundaries

### 4.1. Модуль НЕ выполняет

| Исключено | Ответственный элемент |
|---|---|
| Формирование торговых решений, рекомендаций и оценок | Модули торгового потока TIP |
| Работа с рыночными данными | Data Intelligence Engine |
| Обработка новостей, событий эмитентов, отчётностей | News/Catalyst & Event Risk Module |
| Данные по доступности и стоимости заимствования бумаг | Short Selection Module |
| Запись в Decision & Event Journal | Модули TIP (собственный раздел Logging каждого модуля) |
| Фиксация ручных действий трейдера в терминале | Session Event Log |
| Оценка дисциплины и поведения трейдера | Trader Behavior & Discipline Module |
| Определение политики доступа | Access Control |
| Хранение и чтение паролей, токенов, ключей API | — (исключено полностью) |
| Отправка сообщений от имени трейдера | Трейдер лично |
| Любые действия в личном кабинете IBKR (переводы средств, изменение реквизитов, настройки маржи) | Трейдер лично |
| Установка, обновление, удаление ПО | Не входит в v0.1 (см. Future Extensions) |
| Изменение конфигурации рабочего места | Не входит в v0.1 (см. Future Extensions) |
| Удаление данных по Retention Policy | Не входит в v0.1 (см. Future Extensions) |

### 4.2. Односторонность связей

Модуль читает состояние системы и внешних сервисов. Ни один модуль TIP не читает выходы System Assistant и не зависит от них. Отсутствие обратной связи является технической гарантией изоляции модуля от торгового процесса.

### 4.3. Временна́я граница

Выполнение модуля завершается до старта первого модуля торгового дня. Одновременное выполнение с модулями TIP не допускается.

### 4.4. Границы уровней доступа

| Уровень | Содержание | Версия |
|---|---|---|
| Read | Наблюдение и отчёт. Изменения состояния системы отсутствуют. | v0.1 |
| Prepare | Подготовка действия и предъявление его трейдеру без выполнения. | Future |
| Execute | Выполнение подготовленного действия после явного подтверждения трейдера. | Future |

## Приложение A. Расписание проверок (проект)

| Проверка | Время | Объём |
|---|---|---|
| Утренняя, полная | до старта Market Context (10:00 Вена) | Все области раздела 3.1 |
| Предсессионная, короткая | перед открытием рынка | Только подключения: TWS, IBKR, поставщики данных |
| Пятничная | после закрытия рынка, до запуска Base Universe | Подключения и доступность данных |

Точное время утренней проверки и включение пятничной проверки в состав v0.1 подлежат утверждению.

---

## Приложение B. Future Extensions

- Уровень доступа Prepare: подготовка установки и обновления ПО, переключение конфигурации Home ↔ Travel, очистка данных по Retention Policy, резервное копирование.
- Уровень доступа Execute: выполнение подготовленных действий после подтверждения трейдера.
- Перенос настроек TWS и рабочего места между устройствами. Требование: обязательное резервное копирование перед импортом (совместимость файлов настроек TWS между версиями не гарантируется поставщиком).
- Шаблон личного дневника трейдера: подготовка и открытие формы после сессии, сохранение записи. Заполнение выполняется трейдером.
- Подготовка черновиков сообщений брокеру. Отправка выполняется трейдером.
- Размещение на удалённом сервере. Рассматривается после появления работающего кода платформы.
